# Course Requirements Guide

## Purpose

`course-requirements.md` is the formal record of all decisions made before generating the course. It is the contract between the user and the skill.

---

## Required sections

### Datos generales
- Course name, organization, target audience, age range, modality, number of sessions, total duration per session.
- Time distribution per session: exact minutes for each block (lecture, Kahoot, practice, closing, etc.).
- For courses with special session types (e.g., classes with inspirational talks): include the alternative distribution.

### Material fuente recibido
- What was provided (file name, type).
- Quality assessment: what was strong, what was weak, what was missing.
- How it will be used (preserved as-is, reorganized, complemented, replaced).

### Tecnología disponible
- Devices and connectivity.
- Allowed platforms and tools.
- Specific notes per platform (e.g., Dodona: auto-judge, requires deterministic output).
- Prohibited tools.

### Criterios pedagógicos
- Output language (default: Spanish).
- Gender perspective approach.
- Accessibility framework (UDL, formal).
- Applied pedagogical frameworks: Bloom's revised taxonomy, UDL, active learning, PBL, socioemotional learning, gender-aware STEAM pedagogy.
- Evaluation approach: formative rubric 1–10 per class. No summative assessments.
- Special session notes (inspirational talks, Demo Day, etc.).

### Restricciones y decisiones
- Assumptions made.
- What will NOT be generated (initial/final evaluations, etc.).
- Output format.
- Bibliography base.

### Información faltante
- Any information not provided that may affect course design.
- How it was resolved (assumption made, default applied, or pending confirmation).

---

## Tone

Be precise and direct. This document is a professional reference, not a friendly summary. Use tables where they improve clarity.
