# Main Plan Guide

## Purpose

`main-plan.md` is the complete pedagogical blueprint of the course. It is the document the user approves before any class files are generated. It must be detailed enough that anyone could understand the course without reading the individual class files.

---

## Required sections

### Descripción del curso
One paragraph: what the course is, who it is for, and what students will be able to do at the end.

### Hilo conductor pedagógico
The narrative thread that connects all classes. A guiding question or metaphor that gives the course coherence. Example: "¿Cómo le doy instrucciones precisas a un computador?" for a programming course.

### Estructura del curso
A table with one row per session. Columns:

| Sesión | Título | Contenido central | STEAM woman | Notas |

Notes column: flag sessions with inspirational talks, Demo Day, ceremonies, or any deviation from the standard format.

### Distribución del tiempo por tipo de sesión
A time breakdown table for each session type in the course:
- Standard session.
- Session with inspirational talk (if applicable).
- Ceremony or Demo Day (if applicable).

Each table: block name, activity description, duration in minutes.

### Progresión de dificultad
A visual or narrative description of how difficulty evolves across the course. Can be a text progression diagram or a simple arc description.

### Enfoque de género transversal
How gender perspective is embedded: STEAM women, language, examples, activities, tone.

### Accesibilidad y DUA
Specific adaptations: reference cards, dual instructions (oral + written), multi-level exercises, platform-based self-paced practice.

### Tecnología
Platform list with role and access URL.

### Archivos que se generarán
Complete file tree of the course package, with a one-line description of each file.

---

## Tone

The main plan is a planning document, not full class material. Avoid writing slide content, exercise text, or Kahoot questions here. Those belong in the class files.

The session table is the most important section — it is what the user approves or revises.
